VISIÓN
--------------------------------------------------------------------------------
AntiPC deja de ser un benchmark suelto y pasa a ser una ARQUITECTURA en 5 capas
que unifica tres paquetes del escritorio del autor:

  1. HASHTOOLCODE(l)L()(L ) (L).zip
     - k3hash      → huella, dedup, indexación
     - comunicacion hashcode → permisos de red (HMAC-SHA256)
     - cpp y dll/biblio → Regla Mecánica Universal + MDC

  2. gptcomputing.txt (ChatGPT)
     - Flow Kernel, referencias, Knowledge Resolver, Event Bus
     - Plugins UPS, perfiles de ejecución, UDP como cómputo

  3. AntiPC implementado (este paquete)
     - Benchmarks A→E, industrial, telemetría

FLUJOS DE DATOS
--------------------------------------------------------------------------------

  Auditoría industrial:
    Ruta → K3_FILE → KnowledgeResolver → (reuse|hash)
         → MDC_PHASE(size, modulus) → telemetría CSV

  Análisis numérico (laboratorio):
    N → MDC_FACTOR → factor
      → MDC_REGLA  → producto en escala log

  Red distribuida (ENLAZADA):
    request_network_permission()  →  HMAC local OK
    start_network(hubs=4)         →  spawn hubs + AUTH UDP por hub
    dispatch_remote_hash(payload) →  WORK → hub K3 → RESULT
    pipeline_remote_files(paths)  →  lectura local + HASH en hubs
    stop_network()                →  DONE + apagar procesos

  Protocolo AUTH UDP:
    AUTH_REQUEST → AUTH_CHALLENGE → AUTH_RESPONSE → AUTH_OK
    (HASHTOOLCODE comunicacion hashcode)


LEYES DE LA ARQUITECTURA
--------------------------------------------------------------------------------

  1. Neutralidad del núcleo — Flow Kernel no conoce HASH ni MDC
  2. Consulta antes de ejecutar — KnowledgeResolver.resolve()
  3. Red con permiso — nunca Network ON sin HMAC
  4. Inmutabilidad — Reference frozen
  5. P_util(N) = N·E(N) + K(N)
