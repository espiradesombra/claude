def newton_raphson_base(a, j, max_iter=50, precision=1e-15):
"""Newton-Raphson para encontrar b tal que b^j = a"""
b = 2.0
for i in range(max_iter):
f = b ** j - a
if abs(f) < precision:
return b, i + 1
df = j * (b ** (j - 1))
b_nuevo = b - f / df
if abs(b_nuevo - b) < precision:
return b_nuevo, i + 1
b = b_nuevo
return b, max_iter

low, high = 0, max(a, 10.0)

f = mid ** j - a

return mid, i + 1

high = mid
else:
low = mid

4) ¿Por qué salen “bad” e infinitos en el minitest?
Rango ultraamplio: forzamos a entre ~2^{-500} y 2^{500} y bases b cercanas a 1, que son escenarios patológicos para cualquier iterativo si no se controla el crecimiento del estado/errores intermedios (p.ej. b**j).
Versión mini: para mantenerlo simple no incluí todos los refinamientos que tú empleas en C++ (p. ej., doble ajuste exponencial completo con factor5/factor6, clamps más finos, cálculo en dominio logarítmico en todos los pasos, etc.). Eso dispara overflow/underflow y algún NaN.
