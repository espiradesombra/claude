¡Vamos al grano con esto! Estás mezclando dos conceptos potentes: optimización de cálculo matemático y cómo mover esos datos de forma eficiente mediante hardware.

Aquí tienes el resumen técnico de cómo funciona cada parte y cómo se conectan:

1. El "Cómo y Qué": Cálculo con diff v (Diferenciación Vectorial)
Cuando hablas de diff v en computación, nos referimos a aplicar operaciones de diferenciación sobre vectores de datos (muy común en física simulada, procesamiento de señales o machine learning).

¿Qué hace?: En lugar de calcular el cambio (la derivada) punto por punto de forma secuencial, el sistema operativo o el software de cálculo utiliza instrucciones SIMD (Single Instruction, Multiple Data).

¿Cómo funciona?: El procesador coge un vector completo (un bloque de datos "v") y le aplica la función de diferenciación a todo el bloque a la vez en un solo ciclo de reloj. Esto multiplica la velocidad de cálculo porque aprovecha los hilos y registros de la CPU al máximo.

2. El "Canal": Ethernet vs. Wi-Fi para memoria (Apuntar a Buffer)
Si vas a distribuir el cálculo entre varias máquinas (lo que hablábamos ayer), necesitas mover esos vectores de datos. Aquí es donde entra la elección de la red y el "bufeado":

Wi-Fi vs. Ethernet para Memoria Compartida
Wi-Fi: Tiene demasiada latencia y microcortes. Para cálculos en tiempo real o movimiento de memoria, es el enemigo número uno. Los paquetes se acumulan y el procesamiento se frena.

Ethernet (Cable): Es la clave. Ofrece baja latencia constante y un ancho de banda simétrico. Si usas protocolos como RDMA o RoCE (RDMA over Converged Ethernet), una máquina puede escribir directamente en la memoria RAM de otra a través del cable, saltándose las capas lentas del sistema operativo.

Apuntar a "Buffeado" (Buffering)
Cuando los datos viajan por Ethernet para ser procesados, no se leen sobre la marcha; se hace un apuntamiento a búfer:

El Búfer de Recepción: La tarjeta de red (NIC) recibe los vectores de datos de la red y los almacena temporalmente en una zona reservada de la memoria RAM (el búfer).

Punteros de Memoria: El software de cálculo no mueve los datos de sitio (eso consumiría CPU). Simplemente "apunta" con un puntero de memoria a la dirección de ese búfer.

Ejecución: La CPU lee directamente de ese búfer, aplica el diff v de golpe, y vuelve a dejar el resultado en otro búfer listo para enviar.

Resumen del flujo:
Red (Ethernet) → Llena el Búfer (RAM) → Puntero avisa al software → CPU aplica diff v (SIMD) → Resultado al búfer de salida.

A 20 cm, el problema no es la falta de señal (atenuación), sino todo lo contrario. Que el ancho de banda fluctúe tanto se debe a tres factores físicos:

Saturación del receptor (Overdrive): Al estar a solo 20 cm, incluso una señal de "baja intensidad" puede saturar los amplificadores de entrada (LNA) de las tarjetas Wi-Fi. Interferencia mutua (Co-canal): Al tener 3 emisores Wi-Fi tan juntos, si operan en la misma banda (por ejemplo, 2.4 GHz o 5 GHz) y canales cercanos, se pisarán constantemente entre sí. El protocolo Wi-Fi (CSMA/CA) obliga a una tarjeta a "esperar" si detecta que otra está transmitiendo. Con tres tarjetas a 20 cm, pasarán más tiempo compitiendo por el aire que transmitiendo datos reales.

Efectos de multitrayecto a corta distancia: A 20 cm, los rebotes de la señal en la propia estructura del hardware o la mesa crean interferencias destructivas muy severas, lo que hace que el ancho de banda oscile constantemente.

2. El impacto en el Búfer: Estrategia de Choque
Como el ancho de banda es variable e impredecible, el sistema de apuntamiento a búfer que veíamos antes no puede ser rígido. Si la CPU espera un flujo constante, el sistema colapsará por falta de datos (underflow) o por saturación (overflow).

Búferes Asíncronos Independientes
No puedes usar un solo búfer para todo. Necesitas configurar un búfer de recepción para cada una de las 3 interfaces Wi-Fi.

Cada tarjeta vuelca lo que recibe en su propia dirección de memoria RAM de forma asíncrona.

El papel del "Puntero de Ping-Pong" (Double Buffering)
Para que la CPU pueda aplicar el diff v (cálculo vectorial) sin detenerse por culpa de las fluctuaciones del Wi-Fi, se utiliza una técnica de intercambio:

Mientras el Wi-Fi 1 y el Wi-Fi 2 están llenando el Búfer A, la CPU está leyendo y procesando los datos del Búfer B (que ya se llenó previamente).

En cuanto el Búfer A se completa (independientemente de cuánto haya tardado el Wi-Fi por sus altibajos), los punteros cambian: la CPU pasa a procesar el A, y las redes empiezan a llenar el B.
