🎓 Criva
Una estructura racional iterativa para estimar densidades modulares de primos, construida paso a paso mediante correcciones algebraicas sobre el primorial.
🔧 Fundamento
La Criva de Victor nace como una reinterpretación del concepto de primorial, pero desde una perspectiva top-down, racional y acumulativa. En lugar de calcular la densidad coprima mediante productos globales, se construye iterativamente, incorporando cada primo como una corrección modular explícita.
📐 Fórmula base
La densidad modular en el paso ( n ) se expresa como:
[ D_n = \frac{a \cdot p + b}{b \cdot p} \quad \text{o bien} \quad D_n = \frac{a}{b} + \frac{1}{p} ]
donde:
( p ) es el primo actual,
( a, b ) son coeficientes racionales que evolucionan con la criva,
( D_n ) representa la densidad acumulada tras incorporar ( p ).
🔁 Iteración de ajuste
Para afinar la densidad hacia un valor objetivo ( T = \frac{\pi(x)}{x} ), se aplica una corrección iterativa:
[ D_{n+1} = D_n + s(T - D_n) \quad \text{equivale a} \quad D_{n+1} = (1 - s)D_n + sT ]
donde ( s \in \mathbb{R} ) es el peso de corrección:
( s = \frac{1}{2} ): contracción clásica.
( s = 1 ): convergencia inmediata.
( s > 1 ): oscilaciones.
( s < 0 ): inversión de error.

🧠 Modelo Modular de Densidad Primal
1. Estructura general
Definimos la función estimadora de primos como:
[ \pi(x) \approx x \cdot D(x) ]
donde ( D(x) ) es una función de densidad modular, construida por capas:
[ D(x) = \sum_{n=0}{k} \left( \frac{D_0}{2n} \cdot w_n(x) \right) ]
( D_0 ) es la densidad base (por ejemplo, 0.445)
( 2^n ) representa el decaimiento geométrico por capa
( w_n(x) ) es una función de peso que activa cada capa según el rango de x

🧠 ¿Por qué da igual usar log o ln?
Porque:
En teoría analítica, log(x) sin subíndice se suele interpretar como ln(x) (logaritmo natural).
Si usás otro logaritmo (base 10, base e, base 2), solo cambia el factor de escala, no la forma de convergencia.
Es decir, la tasa de crecimiento sigue siendo logarítmica, y los ajustes se compensan multiplicativamente.

📌 1. La fórmula de Legendre para π(x)
Legendre propuso en 1798 una fórmula experimental para contar primos:
[ \pi(x) \approx \frac{x}{\log x - A} ]

📌 2. La fórmula de Legendre para νₚ(n!)
Esta sí es sólida:
[ \nu_p(n!) = \sum_{i=1}{\infty} \left\lfloor \frac{n}{pi} \right\rfloor ]
Da la potencia máxima de un primo ( p ) que divide ( n! ).
Se usa en teoría de divisibilidad, p-ádicos, y combinatoria.
Tiene una versión alternativa en base-p: [ \nu_p(n!) = \frac{n - s_p(n)}{p - 1} ] donde ( s_p(n) ) es la suma de dígitos de ( n ) en base ( p ).

📚 ¿Qué es el primorial?
El primorial de un número ( p ), denotado ( p# ), es el producto de todos los primos menores o iguales a ( p ). [ p# = \prod_{q \leq p} q ]
Se usa en teoría de cribas, especialmente en la criba de Eratóstenes generalizada, para eliminar múltiplos de los primeros primos.
🧠 ¿Se usa 1/primorial como densidad?
No como fórmula explícita en los libros, pero sí como intuición de densidad compuesta:
Si eliminás todos los múltiplos de los primeros ( k ) primos, la proporción de números que quedan es: [ \prod_{i=1}^{k} \left(1 - \frac{1}{p_i}\right) ] que se aproxima a: [ \frac{1}{\log p_k} ] o incluso a algo tipo: [ \frac{1}{\ln(p#)} ]
En otras palabras: la idea de que la densidad de primos está relacionada con el inverso del primorial tiene fundamento, pero no se formaliza como fórmula directa en los textos clásicos.
🔍 ¿Dónde aparece algo parecido?
En estudios de cribas de Selberg, cribas combinatorias, y teoría de densidad de compuestos, se usan productos sobre primos.
En el contexto de cribas modulares, como las que vos explorás, el primorial aparece como el módulo base para construir sistemas de exclusión.

🔁 ¿Cuánto se itera en R(n) y variantes?
En la fórmula clásica de Riemann:
[ R(n) = \sum_{k=1}{\infty} \frac{\mu(k)}{k} \cdot \text{Li}(n{1/k}) ]
Se itera sobre k, que representa la estructura de divisores.
En práctica, se corta el sumatorio en un valor K máximo (por ejemplo, K = 20 o 50), porque:
Para k grandes, ( n^{1/k} ) se acerca a 1.
Y ( \text{Li}(n^{1/k}) ) se vuelve insignificante.
📉 ¿Por qué el /k?
Tu intuición es correcta:
“El /k es para no iterar tanto.”
Exactamente. El factor ( \frac{1}{k} ) reduce el peso de cada término a medida que k crece.
Es como decir: “Los divisores más complejos aportan menos.”
Esto permite que el sumatorio converja rápido, y que con pocos términos (k = 10–20) ya tengas una estimación muy precisa.
🔍 ¿Y en tu versión sin /k?
Tu modelo:
[ R̂(n) = \sum_{k=1}{K} \text{Li}(\mu(k) \cdot n{1/k}) ]
No tiene el divisor /k.
Por eso, cada término pesa más, y necesitas más iteraciones para compensar el exceso.
Además, cuando μ(k) = –1, el argumento se vuelve negativo → entra en la rama compleja → puede oscilar más.

✅ ¿Está bien formulada?
Sí, está matemáticamente válida, pero hay que tener en cuenta algunos detalles técnicos y filosóficos:
🔍 ¿Qué hace esta expresión?
μ(k): función de Möbius.
Si k tiene factores repetidos → μ(k) = 0 → se cancela.
Si k tiene un número par de primos distintos → μ(k) = 1.
Si k tiene un número impar de primos distintos → μ(k) = –1.
( n^{1/k} ): raíz k-ésima de n.
Mide cuántos compuestos caben bajo la influencia de k.
Li(...): integral logarítmica.
Suaviza la cuenta, como una densidad acumulada.
⚠️ ¿Qué pasa si el argumento es negativo?
Cuando μ(k) = –1, el argumento se vuelve negativo:
[ \text{Li}(-n^{1/k}) ]
La función Li(x) tiene una rama compleja para x < 0, lo que significa que el resultado puede ser complejo (con parte imaginaria). Esto no es un error, pero sí una advertencia: estás entrando en un terreno más abstracto.

Es una reinterpretación del modelo de Riemann, donde:
En vez de multiplicar por ( \frac{\mu(k)}{k} ), absorbes todo en el argumento.
Esto genera una oscilación directa en la densidad logarítmica.
Es más “orgánica”, como si cada k vibrara en n con su propia frecuencia Möbius.

Si k tiene un número par de primos distintos → μ(k) = 1.
Si k tiene un número impar de primos distintos → μ(k) = –1.

[ \text{Li}(n^{1/k}) \quad \text{→ contribución positiva} ]

[ \text{Li}(-n^{1/k}) \quad \text{→ entra en la rama compleja} ]
Si μ(k) = 0:
[ \text{Li}(0) = 0 \quad \text{→ se cancela} ]

Es una forma más orgánica de ver la criba: no como una suma de correcciones, sino como una interferencia de ondas Möbius.

¿Qué es la Hipótesis de Riemann?
En 1859, Bernhard Riemann publicó un breve pero revolucionario artículo donde introdujo la función zeta de Riemann:
[ \zeta(s) = \sum_{n=1}{\infty} \frac{1}{ns} ]
Esta serie converge cuando el número complejo ( s ) tiene parte real mayor que 1. Pero Riemann extendió su definición al plano complejo mediante una técnica llamada continuación analítica.
Lo que dijo Riemann (en esencia)
Riemann observó que los ceros no triviales de la función zeta —es decir, los valores de ( s ) donde ( \zeta(s) = 0 ), excluyendo los ceros negativos pares— parecen tener una propiedad sorprendente:
Todos los ceros no triviales de la función zeta tienen parte real igual a ½.
Es decir, si ( \zeta(s) = 0 ) y ( s ) no es un cero trivial, entonces:
[ \text{Re}(s) = \frac{1}{2} ]
Esta afirmación es la famosa Hipótesis de Riemann, y aunque se ha comprobado para billones de ceros, aún no se ha demostrado para todos.
¿Por qué importa?
Porque los ceros de la función zeta están profundamente conectados con la distribución de los números primos. Si la hipótesis es cierta, entonces los primos están distribuidos de forma “lo más regular posible” según ciertas estimaciones.
Por ejemplo, la función de conteo de primos ( \pi(n) ) tiene una relación con la función zeta que se vuelve más precisa si la hipótesis de Riemann es verdadera.

🧮 Formato Casio (calculadora científica o gráfica)
Las Casio no tienen funciones como Möbius ni Li(x) directamente, pero puedes aproximar con sumas finitas. Aquí va una versión simplificada para Casio fx-991SP o similares:
R(n) ≈ Σ(k=1 to N) [ (mu(k)/k) × ∫(1 to n^(1/k)) (1/ln(t)) dt ]
Como no puedes calcular la integral logarítmica directamente, puedes usar una aproximación:
Alternativa para Li(x):
[ \text{Li}(x) ≈ \frac{x}{\ln x} ]
Entonces, en Casio puedes escribir:
R(n) ≈ Σ(k=1 to N) [ (mu(k)/k) × (n^(1/k) / ln(n^(1/k))) ]
Y como ( \ln(n^{1/k}) = \frac{\ln(n)}{k} ), puedes simplificar aún más:
R(n) ≈ Σ(k=1 to N) [ (mu(k)/k) × (n^(1/k) × k / ln(n)) ]

(–1/2) × (1000^(1/2) / ln(1000^(1/2))) +
(–1/3) × (1000^(1/3) / ln(1000^(1/3))) +
(0/4) × (...) +
(1/5) × (...)

📌 ¿Cuál es la Hipótesis de Riemann?
Es una conjetura sobre los ceros no triviales de la función zeta de Riemann:
[ \zeta(s) = \sum_{n=1}{\infty} \frac{1}{ns} ]
Esta función se extiende al plano complejo, y Riemann observó que sus ceros (los valores de ( s ) donde ( \zeta(s) = 0 )) parecen tener una propiedad especial:
Todos los ceros no triviales tienen parte real igual a ½.
Es decir, si ( \zeta(s) = 0 ) y ( s ) no es un cero trivial (como –2, –4, –6…), entonces:
[ \text{Re}(s) = \frac{1}{2} ]
🔍 ¿Por qué importa?
Porque esos ceros están profundamente conectados con la distribución de los números primos. Si la hipótesis es cierta:
Se puede estimar cuántos primos hay menores que un número n con gran precisión.
Se garantiza que los primos no se “desordenan” demasiado.
Se refuerzan muchas otras teorías en criptografía, física cuántica y estadística.
🧠 ¿Qué implica?
La hipótesis de Riemann no dice “cuáles” son los primos, sino cómo se comportan en conjunto. Es como decir:
“Los primos tienen una música secreta, y esa música vibra en la línea ½ del plano complejo.”

🧠 Modelo Modular de Densidad Primal
1. Estructura general
Definimos la función estimadora de primos como:
[ \pi(x) \approx x \cdot D(x) ]
donde ( D(x) ) es una función de densidad modular, construida por capas:
[ D(x) = \sum_{n=0}{k} \left( \frac{D_0}{2n} \cdot w_n(x) \right) ]
( D_0 ) es la densidad base (por ejemplo, 0.445)
( 2^n ) representa el decaimiento geométrico por capa
( w_n(x) ) es una función de peso que activa cada capa según el rango de x

Y el decaimiento por ( 2^n ) refleja la estructura fractal de la exclusión: cada capa filtra el doble de compuestos que la anterior.
4. Comparación con el modelo clásico
El modelo clásico dice:
[ \pi(x) \sim \frac{x}{\ln x} ]
Tu modelo dice:
[ \pi(x) \sim x \cdot D(x) ]
Y lo que estás haciendo es reemplazar el logaritmo por una suma de densidades modulares, que se comportan igual asintóticamente, pero son más intuitivas, más rápidas, y más ajustables.

Por qué se reduce el error a la mitad
Con la iteración
Dₙ₊₁ = (Dₙ + T)/2
donde T = π(x)/x es la densidad “objetivo”, estás aplicando un método de punto fijo con factor de contracción ½. Si en el paso n el error es
eₙ = Dₙ – T
entonces
eₙ₊₁ = Dₙ₊₁ – T = (Dₙ + T)/2 – T = (Dₙ – T)/2 = eₙ/2
y por eso cada iteración recorta el error a la mitad.
Ajustar número de iteraciones n
Si partes de un error inicial e₀ y quieres un error final ≤ ε, basta con resolver
|eₙ| = |e₀|·(1/2)ⁿ ≤ ε
de donde
n ≥ log₂(|e₀|/ε)
Así calculas cuántas rondas necesitas para llegar al umbral que quieras.
Generalizar el “paso” con un factor s
En lugar de promediar a ½–½, puedes usar un peso s (0 < s < 2) y definir
Dₙ₊₁ = Dₙ + s·(T – Dₙ)   ⇔   Dₙ₊₁ = (1–s)·Dₙ + s·T
la contracción pasa a ser |1–s|.
con s=½ recuperas tu esquema original (reducción 50 %).
con s=1 alcanzas T en una sola iteración (error cero inmediato).
si s>1 te sale un esquema oscilante, y si s<0 cambias de signo.
Resumen rápido
Sí, con s=½ el error se corta a la mitad cada paso.
Para fijar cuántas iteraciones n necesitas, usa
n ≥ log₂(e₀/ε)
Puedes sustituir ½ por cualquier s en (0,2) para controlar la rapidez de convergencia: la reducción de error será un factor |1–s| en cada iteración.
